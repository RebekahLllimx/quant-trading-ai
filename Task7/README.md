## 三个策略

1. **A · 平台模板基线**：`510300.XSHG`，T−1收盘价高于MA20时目标仓位100%，否则空仓。
2. **B · 双均线 + ATR风控**：`510300.XSHG`，MA10/30趋势过滤、ATR20、2倍ATR移动止损、1%风险预算、50%仓位上限、5%账户回撤暂停。
3. **C · 宽基ETF动量轮动**：`510300.XSHG`、`510500.XSHG`、`159915.XSHE`，每周三用15日对数价格斜率×R²打分，持有最高正分ETF的50%，否则持有现金。15日参数由开发期与验证期的15/20/30日邻域检验确定。

A保留平台模板的简洁结构，作为比较基线；B增加趋势过滤、波动止损和账户回撤控制；C把单标的择时扩展为多ETF横向选择。三者分别对应规则基线、单资产趋势风控和多资产动量轮动，便于观察复杂度增加后收益、回撤、换手和空仓时间的变化。

## JoinQuant统一设置

- JoinQuant平台回测区间：2019-01-01至2026-07-23
- 本地研究与影子跟踪起点：2016-01-01
- 初始资金：每个策略500,000元
- 基准：`000300.XSHG`
- 频率：日频
- 复权：平台真实价格模式
- 成本：ETF佣金3bp、最低5元、无印花税
- 滑点：比例滑点10bp
- 信息时点：回测启用`set_option("avoid_future_data", True)`；交易信号只使用当时已经完成的行情

平台结果与本地结果可能因数据源复权、开盘成交模型、订单撮合和涨跌停处理不同而产生差异。这些差异会影响收益、回撤和成交次数，因此平台回测、本地回测和影子跟踪分别记录，不通过修改参数强行对齐。

## 本地复现

```bash
python Task7/scripts/update_live_data.py --use-existing-on-error
python Task7/scripts/shadow_engine.py
python Task7/scripts/build_dashboard.py
python Task7/scripts/validate_results.py
```

`update_live_data.py`获取公开行情，网络失败时保留已有数据；`shadow_engine.py`按冻结规则重建三套组合；`build_dashboard.py`打包页面数据；`validate_results.py`检查日期连续性、组合结果、页面字段和账号信息边界。GitHub工作流计划在交易日北京时间18:00运行。

## 数据层级

- **JoinQuant实际模拟**：平台订单、成交、持仓与净值。现阶段已有运行日志，实际收益序列仍等待平台导出。
- **自动影子跟踪**：公开行情按冻结规则重建，用于连续观察，不代表平台实际成交。
- **历史回测**：开发期、验证期和2026样本外结果，用于确定部署基线、比较参数稳定性和分析风险。

平台导出文件可放入`inputs/joinquant/`。文件只保留策略研究需要的日期、代码、订单、成交、持仓、资产和日志字段，不保存账号、密码、Cookie、手机号、邮箱、访问令牌或私有分享链接。
